## 01 阅读方法与系统范围

### 01.01 这套系统能做什么

Swifood Cashier Offline 是把收银业务保存在本机的桌面系统。收银员可使用已有本地账号登录，完成桌台点餐、排队点餐、现金收款、手工录单、折扣、减菜、取消、退款、出餐、完成订单、清台、员工考勤、交接班、报表查看和本地文件导出。断网属于正常使用条件。

系统依赖本机已经准备好的门店资料。账号、菜单、桌台、税务信息、POS 终端号和业务配置由部署或维护人员提前准备；当前客户端没有配套的完整基础资料管理后台。日常操作成功后，数据写入本机 SQLite 数据库，不会自动上传服务器。

### 01.02 当前版本不提供哪些功能

当前纯离线版不提供服务器账号登录、在线 POS/BIR 绑定、在线支付、扫码支付、优惠券核销、服务器同步、后台上传、在线订单接收、打印机设置、小票/厨房/标签打印，以及通过打印机开启钱箱。

不要把语言包里的“打印机”“线上订单”“库存”“菜单管理”等词都当作主菜单。部分旧字段、票据模板、提示语和历史订单信息仍保留兼容用途，但不能据此推断对应操作仍可使用。支付页面只有普通现金和手工录单两条本地结算路径；Grab、Foodpanda 等手工订单类型只是分类，不会连接这些平台。

## 02 首次准备、启动与登录

### 02.01 开始使用前需要什么

**适用对象：**首次部署由维护人员负责，收银员负责核对结果。

开始营业前应具备：已安装的 Swifood Cashier Offline、可用的本地账号与密码、所属餐厅与收银配置、本地菜单与规格/加料、实际使用的本地 POS 数据，以及需要的桌台和图片。拍照打卡开启时还需要可工作的摄像头。BIR 和商场文件使用相应已准备好的本地资料。

**操作建议：**店长先安排一笔测试流程验收菜单、金额、订单状态和报表；测试必须使用测试环境或明确的测试数据处理方案。本手册不会提供默认账号、默认密码，也不建议在生产门店用真实订单尝试不确定的操作。

**重要前提：**安装程序可以创建数据库结构，但不等于会自动创建门店、账号、菜单或 POS。空库无法靠“联网同步”补齐。

### 02.02 启动应用并选择语言

1. 在 Windows 桌面或开始菜单打开 **Swifood Cashier Offline**。
2. 在登录页右上角选择语言：English、中文、ភាសាខ្មែរ（高棉语）或ภาษาไทย（泰语）。
3. 确认进入账号登录页。若应用恢复已有有效登录，也可能直接进入业务页面。

如果窗口内容不完整，先最大化窗口，再滚动页面内部列表或侧栏。部分列表独立滚动，底部按钮可能在对应区域下方。生产包禁用了 Ctrl+R 刷新；应使用页面“刷新”按钮，必要时正常关闭后重新打开应用。

### 02.03 使用本地账号登录

**入口：**登录页。

1. 输入已配置的账号。字段可能显示“邮箱/Email”，实际校验的是本地保存的账号。
2. 输入该本地账号密码。
3. 按需勾选“记住密码”。该选项用于下次回填登录资料，不等于免除账号校验。
4. 点击“登录/Login”，等待操作完成。
5. 若出现拍照和开班资金弹窗，按 02.04 操作。

**成功结果：**系统恢复本地真实 POS 终端号，进入默认业务页面。登录不要求选择或绑定 BIR/POS，不弹出历史日报通知。历史日报的补生成在后台静默进行。

**失败处理：**账号不存在或被停用可能提示 `Account is not found`；密码不正确提示 `Password is incorrect`。缺少本地餐厅配置或 POS 时，交给维护人员检查本地数据，详见 16.01—16.03。线上账号、联网或重装不能代替本地数据准备。

### 02.04 登录打卡、照片和开班资金

**触发条件：**当前账号开启考勤，且没有尚未结束的本地班次。

1. 登录成功后，若门店开启拍照打卡，先允许摄像头工作，点击“拍照”，核对照片，可按界面“重新拍照”重拍，再确认。
2. 登录拍照属于必经步骤，该流程没有普通取消入口。摄像头不可用时按 16.15 处理。
3. 系统创建上班记录后，进入“开班资金/Opening Fund”弹窗。
4. 输入本班次开始时的备用现金，最多两位小数，例如 `500.00`，点击“确认”。金额按界面货币单位输入，不要输入“分”。
5. 如果门店确定本班次开班资金为 0，可点击“自动计算”。**当前登录流程的“自动计算”实际按 0 提交，不会替你清点钱箱或读取上班余额。**

**成功结果：**开班弹窗关闭，可开始业务。已有进行中班次时，重新登录通常不会重复创建上班卡和重复弹开班资金。考勤关闭的账号不经过这条自动打卡流程。

### 02.05 登录后为什么进入不同页面

默认首页由本地门店配置决定：只开桌台点餐就进入桌台管理；只开排队点餐就进入排队点餐；两种都开时按收银模式进入，排队模式进入排队点餐，其余进入桌台管理；两种都关时进入线下订单。

这是正常配置行为。普通“设置”页面没有点餐开关编辑器，需要改变模式时联系维护人员准备或调整本地配置，不能在不存在的菜单里寻找“切换收银模式”。

## 03 主菜单地图：最多 7 个功能

### 03.01 主菜单的数量与每一项用途

**入口：**一级页面左上角菜单图标。二级页左上角通常是返回箭头，先返回一级页再打开菜单。

当前主菜单定义 **7 项业务入口**。桌台管理和排队点餐分别受门店开关控制，因此实际可能显示 5、6 或 7 项；其余 5 项保留。“交接班”和“退出登录”是底部操作，不计入这 7 项；隐藏日志页面也不计入主菜单。

| 序号 | 中文菜单 | 常见英文名称 | 作用 | 显示条件 |
| --- | --- | --- | --- | --- |
| 1 | 桌台管理 | Table Management | 按区域和桌台点餐、加单、结账、换桌及清台 | 开启桌台点餐 |
| 2 | 排队点餐 | Counter Ordering | 堂食/外带点餐、现金结算及取餐处理 | 开启排队点餐 |
| 3 | 线下订单 | Offline Orders | 查询历史与进行中订单、接单、取消、出餐、完成、退款、电子凭证 | 保留 |
| 4 | 收银员报告 | Cashier Reports | 班次报告、产品汇总、当前班次提取现金 | 保留 |
| 5 | 日终报告 | Z-Reading Report | 日终汇总、保存日报快照、BIR 和 E-Journal 导出 | 保留 |
| 6 | 员工管理 | Staff | 员工签到、休息、恢复工作、签退 | 保留 |
| 7 | 设置 | Settings | 系统信息、语言选择、商场认证文件设置与补生成 | 保留 |

### 03.02 通用界面怎么操作

页面顶部中间显示当前页面名。菜单打开后点击目标项进入；点击遮罩可关闭侧栏。侧栏底部显示角色、姓名和登录时间。不要只看账号名称判断退款权限。

桌台页和排队点餐页有带数字角标的订单按钮，打开“待处理订单”。角标代表未完成订单数量，不是当天销售数量，也不是未付款数量；已付款但尚未完成的订单也可能计入。

金额、折扣、服务费确认以结账页明细为准。页面没有明确“成功”提示或订单状态没有核实前，不要因为按钮按过一次就认定已完成操作。

### 03.03 哪些基础资料不能在这里维护

“员工管理”主要是考勤，不是新增账号、改密码或分配角色的页面；菜单页虽然可能显示“菜单管理”，实际是选择菜品下单，不是新增菜品或调价的后台；设置页也没有税务审批、POS 绑定、打印机、网络或全量同步设置。

需要新增/停用账号、改密码、配置退款权限、改菜单价格、增加桌台、调整税务/服务费/自动出餐规则时，应由维护人员按本地部署方案处理。不要直接改生产数据库或借用其他门店 POS 资料。

## 04 一天营业的操作顺序

### 04.01 开店检查清单

1. 核对 Windows 日期、时间及门店实际使用时区，避免影响票据、考勤和报表期间。
2. 打开应用，用本人本地账号登录，完成需要的拍照和开班资金。
3. 打开“设置 → 系统设置”，核对餐厅名称和 POS 终端号。
4. 查看菜单是否完整、价格是否正确、桌台区域是否符合现场。
5. 打开待处理订单，确认前次未完成业务，交由店长安排继续处理。
6. 若当天需要税务或商场文件，确认对应资料、保存目录和历史日报已准备。

以上是门店操作建议，不表示系统提供一个名为“开店检查”的按钮。

### 04.02 桌台餐后结账的典型流程

桌台管理 → 选择桌台 → 设置人数 → 选菜/规格/加料 →“下单”→ 需要时再次选菜并下单加菜 → 待顾客结账时点“结账”→ 核对整单明细、折扣和服务费 → 输入实收现金 →“收银”→“确认已收款”→ 支付成功 → 完成页面流程 → 根据提示清台或在订单中完成。

“下单”用于先把菜保存到本机，之后才结账；“结账”进入金额和收款流程。餐后点餐可出现原单（界面显示“首次下单”）和多个加单，结账要核对整组订单，不要把加单当成独立结算。

### 04.03 桌台餐前收款的典型流程

桌台管理 → 选择桌台 → 选菜和人数 →“结账”→ 核对金额 → 输入现金 →“收银”→“确认已收款”→ 支付成功 → 按订单状态进行后续履约和完成。

餐前模式的菜单选择和首次进入结账页属于临时草稿，真正订单在收款流程中创建。返回上一级、切换页面或重启可能丢失尚未提交的选择；不能把未收款的临时草稿当作已提交订单。

### 04.04 排队点餐的典型流程

排队点餐 → 选择堂食/外带 → 选菜、规格、加料和备注 →“结账”→ 现金收款并确认 → 在线下订单或待处理订单查看取餐号与状态 → 已接单后“出餐”→ 待取餐后“完成”。若门店开启自动出餐或自动完成，后续状态可能自动变化。

### 04.05 关店与交班建议顺序

先停止接新单并处理未完成订单 → 让收银员核对当前班次报告、提现和实际现金 → 由店长在营业交易结束后检查日终并生成所需日报/导出文件 → 收银员完成交接班签退 → 正常退出应用 → 按门店制度备份。

“交接班”结束员工班次；“生成日终报告”保存门店/POS 报告周期；“退出登录”切换账号；关闭窗口退出程序。四者用途不同，不能互相替代。门店可根据分班和关店安排调整先后，但日报应在确认当日业务结束后生成。

## 05 功能一：桌台管理

### 05.01 查看区域、桌台和占用情况

**入口：**主菜单 → 桌台管理。

右侧列出区域名称；点击区域可定位对应桌台区域。每张桌台卡片显示桌名、相关时间提示和订单状态，最多显示两个状态，多订单时有“查看更多”提示。

待处理订单优先显示。某些已支付待完成的桌台会显示红色背景/边框；蓝色常用于待处理提示；白色不一定能独立证明桌台空闲。**应结合状态标签和实际订单核对，不要只按颜色判断。**

点击桌台卡片进入点餐页。如果系统提示是否完成已有订单/清台，先确认顾客已结束用餐再决定；清台会完成符合条件的订单，不是仅清除一个视觉标记。

### 05.02 为桌台点菜、选择规格和加料

**前提：**桌台点餐已开启，菜单已经准备。

1. 在桌台管理中选择正确区域和桌台。
2. 检查右上桌号/桌名；需要时点击人数旁编辑图标设置顾客人数，最少 1 人。
3. 在左侧按分类浏览菜品。没有可点商品的空分类不会显示。
4. 点击商品。只有一个规格且没有加料的商品会直接加入右侧订单摘要；其他商品弹出选择窗口。
5. 在弹窗中核对规格、价格和加料。规格必选；标注必选的加料组必须选择。当前加料组界面使用单选。
6. 点击确认，把商品加入摘要。
7. 用摘要中的“+ / −”或数量输入调整数量。数量改为 0 会移除该条尚未提交的商品。
8. 同规格且加料组合相同的商品会合并数量；加料不同的同一商品作为不同条目显示。

**结果：**右侧摘要显示本次选菜及合计，尚需按本店餐前/餐后流程继续。确认前发现错误可在摘要中修改；已下单的菜品需要按 07.07 减菜，不能靠修改新草稿撤销旧订单。

### 05.03 备注怎么填写

**入口：**有选中菜品时，订单摘要标题旁编辑图标。

输入本次订单的特殊要求，如“少辣、分开装”，确认后再下单或结账。备注绑定当前选菜批次，随这次订单提交；全部移除所选菜品后备注会清空。需要核查已提交备注时，进入线下订单详情的特殊说明，不要假设新备注会修改以前所有加单。

### 05.04 餐后模式：先下单、后加单、最后结账

**入口：**桌台点餐页；门店配置为餐后结账。

1. 选好本次菜品，点击“下单”。
2. 等待本地保存成功，右侧本次草稿清空。
3. 顾客加菜时，在同一桌台继续选菜，再点击“下单”，形成加单。
4. 需要结账时点击“结账”。若右侧还有新选菜，系统会先提交这批菜再进入结账；没有新菜时查找当前桌台待结账订单。
5. 在结账页逐项核对“原订单”和“加单”，再收款。

**结果：**同一订单组的菜品一并结算。系统没有厨房打印，现场应按门店约定把点餐信息交给厨房；下单成功不表示厨房收到纸票。

**异常：**没有选菜且桌台没有待结账订单时，系统提示该桌没有订单。若已有订单找不到，按 16.05 检查日期、桌台与订单状态。

### 05.05 餐前模式：直接进入结账

**入口：**桌台点餐页；门店配置为餐前收款。

选择菜品、人数和备注后点击“结账”。该模式通常不显示餐后使用的“下单”按钮。进入结账页后核对金额并完成现金确认。

**成功标志：**收款成功提示及订单已付款状态。仅进入结账页不代表订单已正式保存；第一次点击“收银”会进入创建订单/支付记录步骤，关闭现金确认弹窗也不等于撤销已创建记录。遇到中断应先查线下订单，避免重新录一笔。

### 05.06 查看指定桌台的订单列表

**入口：**桌台点餐页 → 左下展开操作 → 订单列表。

1. 选择日期范围。页面初始范围为三天前至今天，按创建时间查询。
2. 从左侧选中订单组。
3. 右侧核对原订单、加单、规格、加料、数量和金额。
4. 点击“结账”进入选中订单结算；或点“编辑订单”选择“取消订单”“换桌”。

这个桌台列表用于可处理的订单，不等同于“全部历史订单”。查看完成、退款等历史状态，请用主菜单“线下订单”。先选中订单再操作，否则会提示先选择订单。

### 05.07 换桌怎么操作

**入口：**桌台点餐页 → 展开操作 → 订单列表 → 选中订单 → 编辑订单 → 换桌。

1. 核对要换桌的订单与顾客。
2. 在换桌弹窗选择目标区域，再选择目标桌台。
3. 点击“保存更改”。
4. 成功后回到桌台管理，检查新旧桌台状态以及目标订单的桌名。

**结果：**订单组迁移到目标桌台；原订单和加单属于同一组，不能只凭一条菜品判断迁移结果。目标桌存在尚需处理的订单时可能阻止换桌，应先完成或取消目标桌订单，再重新选择。已完成订单不可按进行中订单换桌。

### 05.08 清台与完成订单

**入口：**桌台点餐页 → 左下展开操作 →“完成”；或者支付后/再次进入桌台时出现的清台确认。

清台前应确保相关订单已支付且已进入可完成状态。对未付或待接单等阻塞订单，先在“线下订单”或“待处理订单”处理，不能用清台跳过收款。确认清台后，系统把符合条件的相关桌台订单完成，释放桌台业务占用，历史记录仍然保留。

门店若开启自动清台，符合条件的餐后桌台支付完成返回桌台页时可直接执行清台；否则可能弹出人工确认。没有弹窗并不一定是故障，需结合模式、是否带回桌台信息及当前订单状态判断。

**注意：**当前清台逻辑主要处理最近三天范围内的相关订单。历史遗留占用、缺少桌台标识或清台后仍异常，交维护人员核对，不要删除数据库记录。

## 06 功能二：排队点餐

### 06.01 排队订单怎么创建

**入口：**主菜单 → 排队点餐。

1. 在右侧选择“堂食”或“外带”。
2. 点击商品，选择所需规格和加料。
3. 调整数量，按需填写订单备注。
4. 核对当前摘要，点击“结账”。
5. 在结账页完成现金收款，具体见 07.02。

排队点餐始终走餐前收款路径，进入结账前的选菜是临时草稿；成功支付后才继续处理履约。排队点餐没有桌台换桌流程，普通排队结账的服务费按当前本地逻辑为 0。

### 06.02 怎样查看取餐号、出餐和完成

**入口：**排队点餐页订单角标 → 待处理订单，或主菜单 → 线下订单。

1. 完成收款后找到这笔订单，核对取餐号、堂食/外带和菜品。
2. 订单若仍在已付款待处理状态，使用“接单”。普通本地支付通常会自动推进到已接单，因此不一定还显示接单按钮。
3. 菜品准备好后，对“已接单”排队单点击“出餐/Serve”，进入“待取餐”。
4. 顾客取走餐品后点击“完成”，使订单进入已完成。

自动出餐或自动完成开启时，部分步骤可能已经自动发生，以当前状态为准。取餐号是现场识别号码，不应与商户订单号、内部订单号或 SI 发票号混用；取餐号不是永久全局唯一编号。

### 06.03 排队订单未收款或顾客取消

未付款且处于待处理的已创建排队订单可按状态选择取消；已付款后应按退款流程处理，不能用取消代替退款。排队未付款订单存在创建后 15 分钟自动取消规则，前提是正式本地订单已经创建且仍符合未付款待处理条件。尚未提交的菜单草稿不属于定时取消订单。

如出现已付款但顾客未取餐，不要重新收款；先核对支付状态，再安排出餐、完成或按店长决定退款。

## 07 共用操作：结账、现金、折扣和减菜

### 07.01 结账页看什么

**入口：**桌台点餐、桌台订单列表、线下订单或待处理订单中的“结账/Bill Out”。

结账页主要包含折扣与支付方式、订单摘要与账单明细、现金输入区。收款前核对桌台/订单、顾客人数、原订单和加单、有效商品数量、商品小计、促销折扣、服务费、PWD/SC 折扣、减免 VAT、附加费（手工录单时可能出现）和最终总额。

需要时点击“查看增值税明细”展开税务分项。税额与服务费受本地门店和 BIR 配置影响，不应只拿菜单草稿合计与最终实收作简单比较。界面金额是常用货币单位，例如 `100.00`；内部存储使用最小货币单位，由系统自动转换。

### 07.02 普通现金收款：完整步骤

**前提：**订单可结账、金额已核对、顾客已实际交付现金。

1. 确认支付渠道为 `CASH`。普通离线收款默认使用该渠道。
2. 在右侧数字键盘输入实收金额。例如应收 `128.50`、收到 `200.00`，输入 `200`，找零应为 `71.50`。
3. 确认实收不少于应收，检查找零。
4. 点击“收银/Charge”。
5. 在现金确认弹窗再次核对小计、折扣、服务费、总额、实收和找零。
6. 确认现金已收到后，点击“确认已收款/Cash Received”。
7. 等待“支付成功”，按应显示的“完成”按钮返回业务页面。
8. 如有清台提示，确认顾客业务已结束后再处理；排队单按出餐/取餐流程继续。

**完成边界：**本地确认收款成功才代表该次现金支付完成。点击“收银”只进入创建支付记录和确认环节，不等于确认收钱；支付成功弹窗中的“完成”用于结束页面流程，也不应被理解为所有订单都已完成履约。

本系统不会自动打印或自动开钱箱。系统记录的是现金收付业务，实体现金的接收和找零仍由收银员执行。

### 07.03 现金键盘和快捷键

可用屏幕数字键或物理键盘输入数字和小数点。最多保留两位小数；删除图标/Backspace/Delete 删除末位，底部“清空”清除整个输入。

非输入框编辑状态下、没有弹窗且收款条件满足时，Enter 可触发收款。输入姓名、备注、金额表单等字段时，快捷键不会按普通收款处理。

**当前输入限制：**现金键盘不接受空输入时直接以 `0` 或 `.` 起始，因此不能正常直接录入 `0.50` 这类不足 1 个货币单位的实收。这是当前实现的限制，普通门店操作没有在本次核对中确认可用的录入方案。遇到时请店长/维护人员处理，不要把 `0.50` 误录成 `50`，也不要虚填收到的现金。

### 07.04 固定快捷折扣和自定义折扣

**入口：**结账页左侧“折扣”。

快捷折扣提供减免 `5%`、`10%`、`20%`、`50%`。这里是减去该百分比，例如减免 20% 相当于支付商品原价的 80%，不要理解成“二折”。

使用快捷折扣：点击所需比例，检查账单中的促销折扣与总额；再次点击当前已选比例可取消。切换到其他折扣时会替换当前选择，不是把多个折扣叠加。

自定义折扣：点击“自定义/Custom”，选择“百分比”或“固定金额”，输入数值并确认。百分比最大 100，确认值必须大于 0；固定金额按界面货币单位输入。选择后再次点自定义可清除该选项。部分输入框币种符号固定显示为菲律宾比索，应以门店币种和最终账单核对。

**结果：**普通促销折扣影响结账金额。不要为了配平现金随意输入超出合理订单金额的折扣；当前界面没有完整的经理审批流程，折扣使用应遵循门店制度。

### 07.05 PWD/SC 折扣怎么使用

**用途：**PWD 为残疾人折扣，SC 为老年人折扣；当前实现主要对应菲律宾门店业务。是否显示取决于本地门店 PWD/SC 开关。

1. 先核对就餐总人数。多人订单的人数影响优惠分摊。
2. 在结账页点击 PWD 或 SC。
3. 多人订单填写“享受折扣人数”，范围为 1 至总人数；单人时按单人处理。
4. 填写享受优惠者姓名和证件号。姓名最多 50 字符、证件号最多 30 字符。
5. PWD 还需选择有效日期；SC 表单不要求该有效日期字段。
6. 提交，核对客户信息、PWD/SC 折扣及 Less VAT 明细。
7. 确认无误后完成收款。

系统按人数比例、税务配置和本地舍入计算优惠；不要把所有 PWD/SC 情况一律按含税总价直接乘 80%。改变总人数会清空已计算的普通 PWD/SC 折扣，应重新录入并核对。改用快捷/自定义折扣也会替换当前优惠。

证件号按当前餐厅、当前 POS 和本机自然日校验，PWD 与 SC 分组独立，去除首尾空格并忽略大小写比较。已退款等相关历史交易仍可能参与同日占用判断，不能承诺“退款后立刻可重复使用”。这不是跨门店联网资格核验。

### 07.06 服务费怎么查看和调整

服务费由门店本地配置决定：关闭、固定金额、百分比或自定义。普通排队订单的结账不收取该服务费。桌台使用预设固定/百分比时系统自动计算，不一定出现手工编辑入口。

**自定义服务费入口：**结账页左侧服务费金额区域，仅在适用配置下显示。

点击服务费 → 选择百分比或固定金额 → 输入大于 0 的数值 → 确认 → 核对明细和总额。当前弹窗不接受用 0 作为确认值；需要免收或更改固定配置时，应确认门店配置及维护方案，不要编造“输入 0 保存”的操作。

含税商品的百分比服务费以未税销售额为计算基数；因此它可能不等于屏幕含税小计直接乘费率。手工录单采用独立金额逻辑，应在手工录单流程中核对。

### 07.07 已下单商品如何减菜

**入口：**适用的已创建桌台订单 → 结账页 → 订单摘要旁减菜/编辑图标。

**条件：**订单未支付，且处于待处理或已接单等允许编辑状态。普通菜单草稿直接在摘要调整；已经付款的单据不能靠减菜修正。

1. 打开目标订单结账页，进入减菜状态。
2. 对要减少的菜调整“剩余数量”。例如原来 3 份、退掉 1 份，填 2；全部退掉填 0。数量不能大于原数量。
3. 核对修改行，点击“确认”。点“取消”仅放弃本次减菜草稿。
4. 保存后重新核对商品、小计和总额。
5. **重新设置需要的折扣或手工录单信息。**减菜成功后原有相关结算草稿会清空，不能沿用旧优惠计算。

全部有效商品减为 0 时，系统会取消整单并提示订单已取消。已减少/取消的明细可保留追踪痕迹，不应因为看到划线项就认为仍重复收费。要增加已下单菜品，请回到桌台点餐加单。

### 07.08 收款中断、重复点击或状态不明

**原则：先查询，再决定下一步。**收款过程中应用关闭、弹窗被关闭、页面卡顿或报错时，可能已经创建订单/支付记录，也可能尚未确认成功。不要立即重选商品再录一笔。

在线下订单中按时间和桌台找原单，检查支付状态、SI/收款信息、订单追踪和是否已有退款。已支付的单不应再次收款；未支付但订单已存在时应继续处理原单。无法判断时记录时间、订单号、POS、实际收到/退回现金金额和错误文字，交店长或维护人员核对。

## 08 共用操作：手工录单

### 08.01 手工录单适合什么场景

**入口：**先选择菜品进入结账页 → 支付方式区域“手动录单/Manual Order”。

用于把已经按纸质凭证或其他人工方式确认的交易录入本机，也可按门店规定记录外部渠道分类。它仍需要菜品/订单基础，用来形成商品和报表记录，不是一个空白的任意收支记账入口。

手工录单不发起第三方扣款，不验证外部平台是否到账；选择 Grab 等类别不会拉取平台订单。应先依据真实凭证核对交易，避免把已经录过的交易重复录入。

### 08.02 手工录单完整操作

1. 选择对应商品或打开待结算订单，进入结账页。
2. 点击“手动录单”。
3. 若门店税费配置要求，填写纸质 SI/OR 号码；没有该字段时按界面继续。
4. 选择“订单类型”。选项依门店国家变化，可包括堂食、外带、配送、Grab、Foodpanda、ShopeeFood、GoFood、其他；并非所有门店都显示全部类型。
5. 如适用，选择 PWD/SC 并填所需姓名、证件号、PWD 有效日期。此项同时受国家和门店优惠开关影响。
6. 输入凭证对应“总金额”，最多两位小数，界面允许范围 0 至 100000；填写备注（最多 500 字符）方便追踪。
7. 点击弹窗“确认”。此时校验编号、金额和优惠，返回结账页并进入手工录单状态。
8. 再次核对左侧手工 SI/OR、订单类型、金额、附加费/折扣以及备注。
9. **点击结账页“收银/Charge”**，等待支付成功，再完成页面流程。
10. 在线下订单中检查记录、已付状态和金额。手工录单成功后按本地逻辑成为已付款、已完成订单。

**关键区别：**第 7 步只是保存当前页面的手工录单草稿；第 9 步才正式提交。手工模式下普通现金数字键盘禁用、找零为 0，这是正常行为，不需要再输入普通现金实收。

### 08.03 手写 SI/OR 格式和重复检查

当前前端限制 SI/OR 为 1—20 个字符，仅允许英文字母、数字和短横线 `-`。刚好 20 位纯数字的编号不可使用，以免与系统自动号码格式混淆。例如 `MAN-20261026-001` 可作为格式示例，是否可用还要通过本地判重。

判重依据本地数据库中同国家餐厅的支付凭证号；不能保证发现其他未迁入本机的数据或外部平台重复编号。弹窗确认和最终提交都会进行相应校验。出现重复提示时先查原凭证和历史交易，不能随意改号把同一笔交易录两次。

### 08.04 手工金额为什么出现折扣或附加费

不使用 PWD/SC 时，手工输入金额与系统商品原始金额的差额可能显示为促销折扣或附加费。例如商品原始额 100、输入 90，会表现为 10 的差额折扣；输入 110，可能出现 10 的附加费。

PWD/SC 手工录单会根据输入实付反算折前金额并校验合理性。若提示金额与系统商品不匹配，应核查凭证金额、税务配置、商品和优惠身份，不要靠随意增加金额绕过提示。

### 08.05 如何退出尚未提交的手工录单状态

**入口：**手工录单状态中的“手动录单”入口。

再次点击会出现取消手工录单确认。确认后恢复普通结账金额、优惠和 CASH 渠道，原实收输入清零，再核对后继续现金收款。普通折扣或服务费区域在手工状态下可能引导取消手工录单，不能把两套金额逻辑混用。

若手工交易已经“收款成功”，这个取消草稿操作不能撤销交易；应在线下订单找到原单，按退款等允许流程处理。

## 09 功能三：线下订单

### 09.01 查询订单和历史记录

**入口：**主菜单 → 线下订单。

1. 左侧顶部选择状态：全部、待接单、已接单、待自提、已完成、已取消或退款。
2. **选择状态后点击旁边“刷新”**，应用该状态筛选。当前实现的状态下拉选择先保存筛选值，不保证立即更新列表。
3. 右上角选择按“创建日期”或“桌台”查找。日期支持起止日期；桌台输入名称。切换查询类型会清掉另一种条件；日期或桌名改变会直接应用查询。
4. 向下滚动左侧订单列表可加载更多，不能把第一页当作全部订单。
5. 点击一张订单卡片，右侧查看完整明细。

找不到订单时先选“全部”、扩大日期范围、清空桌名并刷新。退款筛选对应支付退款状态，并不是一个普通履约状态；已完成订单仍可能后续退款。

### 09.02 订单详情怎么看

订单详情包括商品名称、规格/加料、数量、单价和小计；金额区显示服务费、折扣、历史优惠信息、Less VAT、附加费及总金额；其他信息可能包含创建/完成时间、商户订单号、订单编号、POS 号、SI 号、支付渠道、支付时间、顾客人数、取餐号、特殊说明、退款时间和备注等。

原单和加单属于同一内部订单组。整单详情与支付凭证会聚合有效菜品，已取消子单/减菜行不应作为正数再累加。已付款整单的服务费和税额优先参考最终成功支付快照。

历史数据可能保留在线渠道或优惠券信息，这不代表本版支持新增在线付款或优惠券核销。遇到历史记录字段不完整，应先识别数据来源和迁移情况。

### 09.03 订单状态与付款状态要分开看

| 履约状态 | 含义 | 常见下一步 |
| --- | --- | --- |
| 待接单 / Pending | 正式订单已存在，等待接单或付款等处理 | 按模式收款、接单或取消 |
| 已接单 / Taken | 已接受并进入履约 | 桌台单结账/完成；排队单出餐 |
| 待自提（待取餐） / Ready for Take-out | 排队餐品已准备 | 顾客取餐后完成 |
| 已完成 / Complete | 履约完成 | 查记录、查看凭证，符合条件时退款 |
| 已取消 / Cancelled | 未付等符合条件的订单已取消 | 查看追踪；无需再收款 |

付款状态另有未付款、支付失败、支付成功、退款中、已退款、退款失败等。**“已接单”不等于“已付款”，“支付成功”不等于“已完成”。**旧数据中出现退款中/待退款时，应先核对本地记录，不要重新收款或强行继续履约。

### 09.04 编辑订单中什么时候出现哪些操作

**入口：**选中订单 → 右下“编辑订单”。界面只列出当前允许的动作。

| 场景 | 常见可用动作/限制 |
| --- | --- |
| 桌台餐前、待处理、未付款 | 结账、取消 |
| 桌台餐前、待处理、已付款 | 接单；普通支付可能已自动接单 |
| 桌台餐后、待处理、未付款 | 接单、取消 |
| 桌台餐后、已接单、未付款 | 结账、取消 |
| 桌台、已接单、已付款 | 完成 |
| 排队、待处理、未付款 | 取消 |
| 排队、待处理、已付款 | 接单 |
| 排队、已接单 | 出餐；实际写入还要求可用付款状态 |
| 排队、待取餐 | 完成；实际写入还要求可用付款状态 |
| 已付款/退款失败且符合权限 | 可能显示退款 |
| 已完成、已取消、退款中等 | 相应动作隐藏或受状态校验 |

该表是日常操作判断表，不代表所有历史异常组合均可操作。某些退款失败状态按已付处理；真正提交时本地规则还会复核，按钮可见不保证错误历史数据能通过。

### 09.05 接单、出餐、完成怎么操作

1. 在“线下订单”找到目标单，核对桌台/取餐号和支付情况。
2. 点击“编辑订单”，选择当前需要的“接单”“出餐”或“完成”。
3. 等待成功提示，核对新状态。

“出餐”仅用于排队订单，必须先已接单；“完成”对排队单要求待取餐，对桌台单要求已接单且已付款。退款中订单不能正常继续这些状态流转。操作后如果订单从左侧列表消失，可能只是已不属于当前状态筛选，切换“全部”并刷新确认。

### 09.06 未付款订单如何取消

**入口：**线下订单 → 选中符合条件的订单 → 编辑订单 → 取消。

核对原单，填写取消原因（建议记录顾客取消、误点等实际情况），点击确认，等待取消成功。也可从桌台订单列表或待处理订单走取消入口。

**结果：**订单被标记为取消，保留记录和追踪；这不是删除历史。已付款订单通常需要退款，不能用取消表示退钱。整组取消与减菜不同：只减少部分菜品应在结账页减菜。

### 09.07 已付款订单如何退款

**推荐入口：**线下订单 → 选中原单 → 退款。线下订单详情的退款按钮受账号退款权限控制。

1. 核对原订单、SI、实付金额、支付状态和是否曾经退款。
2. 点击“退款”。按钮不显示时检查当前账号权限及付款状态。
3. 在确认弹窗填写原因备注，按门店制度确认应退金额和现金处理。
4. 点击确认，等待“退款成功”。
5. 刷新并检查已退款状态、退款编号、时间、金额和备注。
6. 需要凭证时查看退款电子副本。

**范围：**当前普通退款入口是整单退款，没有在页面中提供输入“部分退款金额”的表单。不要承诺部分退款、撤销退款或自动原路退回外部支付平台。该纯离线系统记录本地退款，顾客实际现金退还仍须人工完成并对账。

已退款不能重复退款；退款中不能再次启动；未付款不能退款。成功退款会新增退款记录并关联原单，保留原支付证据；未完成订单也会按退款逻辑结束。待处理订单弹窗可能也显示退款入口，涉及敏感操作时应按门店权限制度由授权人员操作，不把“按钮出现”当作充分授权。

### 09.08 查看订单追踪

**入口：**线下订单详情 → 其他信息中的“操作员/追踪订单”链接；待处理订单也有追踪入口。

打开后按时间查看本地记录的下单、支付、接单、出餐、完成、取消、退款等事件。追踪用于确认先后顺序、操作人员和系统自动动作，不代替实际现金清点。问题报修时保留订单号与关键事件时间。

### 09.09 查看支付和退款电子凭证

**入口：**选中符合条件的订单 →“查看电子版/View Digital Copy”。

点击后系统在本地生成凭证图片预览。已退款订单可在弹窗下拉框切换“支付小票”和“退款”副本。不是所有待处理、取消或资料不完整的订单都有该按钮，生成失败时按 16.11 处理。

**边界：**这是应用内预览；当前界面没有承诺一键保存每张预览图片、发送顾客或硬件打印。需要可保存的流水文件使用“日终报告 → E-Journal”。不要把查看副本当作重新收款或重新退款。

## 10 共用功能：待处理订单与自动流转

### 10.01 快速处理待处理订单

**入口：**桌台管理右下圆形订单按钮；或排队点餐底部带角标的订单按钮。

1. 点击角标按钮，打开待处理订单。
2. 用上一单/下一单切换。
3. 核对桌台/取餐号、堂食/外带、商品、人数或取餐号码、金额和状态。
4. 点击当前可用的取消、接单、结账、出餐、完成或退款。
5. 处理后列表和数量会刷新；全部处理完弹窗可能关闭。

角标为 0 时系统会再检查本地真实未完成订单；确实没有会提示“没有待处理订单”，属于正常结果。某单处理后弹窗跳到另一单也属于列表刷新行为。

### 10.02 自动取消、自动出餐和自动完成规则

| 自动动作 | 当前规则 | 操作人员要注意 |
| --- | --- | --- |
| 排队未付款取消 | 正式排队单创建后 15 分钟，仍未付且待处理才适用 | 菜单临时草稿不适用；不要把超时取消当付款成功 |
| 排队自动出餐 | 已付且已接单；门店开启自动出餐并有有效时间配置 | 可立即或延后进入待取餐，不代表厨房真的做好 |
| 排队自动完成 | 已付且待取餐；门店开启自动完成并有有效时间配置 | 状态自动完成不等于现场已核实交餐 |
| 桌台兜底完成 | 已付款且未完成的桌台单，成功支付约三天后 | 是遗留订单处理机制，不应取代日常清台 |

自动规则来自提前准备的本地配置，当前设置界面没有提供这些开关编辑器。应用主进程负责定时任务，不要求一直停留某个订单页；应用关闭时不能执行定时器，重新启动、恢复会话/系统唤醒后会重建检查，符合条件的逾期任务可能随后执行。

### 10.03 订单为什么自己变了状态

先查看订单追踪和时间，确认是否命中自动规则。手动取消、出餐、完成、清台或退款会调整相关待执行任务；系统执行时也会检查当前状态。出现持续不自动流转时，先确认应用仍在运行和本地配置有效，再收集日志交维护人员，不要反复改 Windows 时间催促任务。

## 11 功能六：员工管理

### 11.01 查找员工和查看考勤

**入口：**主菜单 → 员工管理。

每个员工卡片显示姓名、上班/休息/下班操作及相关时间，有本地打卡照片时展示照片。右上“输入姓名”搜索后匹配员工名，不区分英文大小写；清空条件并搜索可恢复全部。

该页用于已有员工的本地考勤，不提供新增员工、重置密码、编辑排班、导出工资或维护角色权限。看到员工列表不等于可以跨人随意操作，门店应明确代打卡和管理操作规则。

### 11.02 上班签到

**入口：**员工卡片 → 上班/IN。

找到正确员工 → 点击上班 → 若要求拍照则拍摄并确认 → 等待保存 → 检查签到时间与照片。已在上班时重复签到会提示“你已签到”，不会作为新班次反复签到。

登录自动签到与员工页手动签到是不同入口。手动签到不保证弹出登录流程的开班资金窗口；如果需要核对该员工班次资金，应查看其收银员报告并按门店维护方案处理。

### 11.03 休息和恢复工作

**入口：**员工卡片 → 休息一下/Break。

已签到且工作中的员工点击休息后进入休息计时页。计时显示从本次休息开始至当前的时长。休息结束点击“恢复工作/Resume Work”，保存后返回员工页。

员工已经休息时再次点休息，只进入已有休息页，不应新建另一段休息。没有签到先提示签到；下班人员不能直接开始休息。仅返回其他页面不代表已结束休息，必须执行恢复工作。

### 11.04 下班签退：自己与其他员工不同

**当前登录员工：**在员工页点自己的 OUT，会进入与侧栏“交接班”一致的流程：先检查未完成订单 → 按配置拍照 → 手头现金 → 班次报告 → 关闭报告后退出登录。详见 14.01。

**其他员工：**点击该员工 OUT，按需拍照并保存本地签退，再刷新列表；不会替当前登录人自动退出。不要认为签退其他员工等于完成了其所有现金交接步骤。

普通员工页 OUT 要求处于工作状态，休息中先“恢复工作”再签退。提示 `No active clock record found.` 时应核对是否已经签退或没有活动班次，不要重复建记录。

## 12 功能四：收银员报告与产品汇总

### 12.01 查看班次报告

**入口：**主菜单 → 收银员报告 → 班次报告。

1. 左侧选择收银员。
2. 选择月份。未来月份不可选。
3. 点击实际班次；尚未签退的最近班次显示为“当前班次”。
4. 右侧加载交易摘要、支付类型、交易数量和总金额。
5. 需要凭证时点击“查看电子版”。

普通员工按真实打卡班次统计；“自助服务/Self Service”是历史/分类统计选项，按日期列出，不代表当前版新增了自助点餐功能。没有班次时先查选中员工、月份与本地打卡记录。

### 12.02 班次资金字段分别表示什么

| 字段 | 使用时的含义 |
| --- | --- |
| 开班资金 / Opening Fund | 班次开始录入的备用现金 |
| 手头现金 / Cash on Hand | 本地资金记录或报表算法得到的现金值；应与实际清点对照 |
| 提取现金 / Less Withdrawal | 班次中登记取出的现金 |
| 已收付款 / Payment Received | 选定报告范围的实付统计，不是商品折前金额 |
| 盈亏 / Short/Over | 报表短溢款计算结果，不等于自动核实现金无差异 |
| 退款金额 | 对应范围内退款统计，需结合交易和退款时间解释 |
| 已取消金额 | 对应报告口径下取消统计，不能当作退给顾客的现金 |

不同报告可能使用不同周期和快照。即使显示盈亏为 0，也仍应人工清点并核对退款、提现、开班资金和订单归属；不要仅凭该字段承诺现金已平账。

### 12.03 当前班次提取现金

**入口：**班次报告 → 选择仍未结束的“当前班次” → 提取现金/Cash Withdrawal。

1. 输入提现备注（必填、最多 20 字符），例如“转交店长保管”。
2. 输入真实取出的金额，最多两位小数，确认保存。
3. 接着出现“手头现金”弹窗，默认值参考当前报告金额扣除本次提现。
4. 实际清点后输入手头现金并确认；也可按门店制度选择自动计算。
5. 刷新查看提现金额和资金信息。

**重要：**提现第一步成功时已经写入本地记录。后续手头现金弹窗取消或自动计算，不会撤销刚才提现，也不会签退班次。发现重复提现或金额错误时不要再用反向金额胡乱补偿；先保留记录交店长核对，当前界面没有提现历史直接编辑/删除入口。

### 12.04 产品汇总怎么查询

**入口：**主菜单 → 收银员报告 → 产品汇总/Summary of Products。

1. 选择一个收银员及其月份/班次，查看对应销售商品；也可选“全部/All”查看时间范围汇总。
2. 选择全部时，可用实时、周、月或自定义日期。
3. 在右侧分类下拉框选择全部或某个商品分类。
4. 查看商品分类、名称、规格、数量、单价、小计及汇总指标；表格可分页。
5. 需要票据形式时使用“查看电子版”。

分类选择会改变屏幕可见商品及可见合计。当前电子副本调用不携带右侧分类筛选参数，不应承诺“当前分类屏幕就是该分类专属电子副本”；用于对账时核对副本实际范围。

### 12.05 实时、周、月、自定义的实际日期口径

“实时”日期选择为今天，当前班次/实时报表会按相应报告逻辑取实际时段。“周报告”预设从今天往前 7 天的零时开始到今天末尾，包含起止日期，可能覆盖 8 个自然日；“月报告”从今天往前 30 天零时到今天末尾，最多覆盖 31 个自然日。它们不是固定自然周或自然月。

需要严格的周一至周日、月初至月末或单日数据时，使用自定义起止日期。自定义日期跨度按当前选择器限制最多相差 30 天，即包含首尾最多 31 个日期。报告最终显示的起止时间比预设名称更可靠。

## 13 功能五：日终报告、BIR 与 E-Journal

### 13.01 查看日终汇总

**入口：**主菜单 → 日终报告 → 日终报告类型。

左侧选择实时、周、月或自定义日期；右侧查看当前累计销售额、过去累计销售额、当日销售额、支付类型统计、销售明细、服务费、折扣、销售调整和 VAT 调整。

日报属于当前门店/POS 的报告口径，不能拿另一终端或所有收银员总数直接比较。某些已生成日报显示的是保存快照而非持续滚动的新合计；应核对实际报告周期和是否已生成。

### 13.02 正式生成日终报告

**入口：**日终报告 → 选择“实时报告” → 生成报告。

1. 确认当天交易处理已结束，核对订单、退款、班次资金和日期。
2. 点击“生成报告”（英文为 End Your Day）。该按钮只在实时选项下显示。
3. 阅读提示并确认。
4. 等待成功。系统先补齐必要历史日报，再保存当前本地日报快照。
5. 需要时点击“查看电子版”查看票据样式结果。

**结果与限制：**生成报告会保存本地状态，不是普通只读刷新，也不会打印。当天已经生成时按钮禁用。日终生成不等于员工签退，也不会自动替你完成尚未付款订单。

日报成功保存后，当前 POS 的后续排队取餐号重新从 `001` 开始；如果配置为 Parqal/Megaworld，还会尝试生成该日报日期对应商场文件。文件生成失败只记日志，不撤销已保存日报，应按 15.04 补生成。

已生成后继续交易不会保证回写已冻结的报告快照。发现漏单、迟到退款或生成过早时，应记录时间和单号交维护人员核对周期，不要删除快照强行重做。

### 13.03 历史日报与实时日报的区别

系统登录恢复会话后会静默补生成符合规则的历史缺失日报，不再弹“自动生成报告”通知。没有弹窗是当前设计。

当天实时查询会参考最近日报的周期；首次周期可能以本地餐厅创建时间或 BIR 审核时间为起点，之后承接既有周期。历史单日查询依赖对应已生成日报；多日查询和单日快照也可能不同。因此“今天”标签不一定意味着绝对从今天 00:00 计算全部来源，核对副本/数据中的实际开始和结束时间。

历史日期提示没有 Z-Reading/End of Day Report 时，应先由维护人员检查历史补生成和当前 POS 数据。界面没有任意历史日期“重新生成日报”按钮；周/月/自定义下也不提供实时页的生成/电子副本按钮。

### 13.04 日终数字如何理解

总销售与服务费分开列示。当前实现的 Gross/NET/累计销售等口径排除单列服务费，退款的服务费也需按原销售周期处理。不要把“销售总金额 + 服务费”和“净销售”混为同一指标。

日终取消金额和 Less Cancelled 当前固定为 0，取消单不参与该金额计算；线下订单里存在取消记录并不意味着日终取消金额必定大于 0。PWD、SC、其他折扣和 VAT 调整分别列示；报表列出某种折扣栏位不代表当前结账页提供这种专用优惠入口。

累计销售、当日销售和收银员实收金额可能因税、折扣、服务费、退款、完成时间及报告周期不同而不相等。对账时先统一 POS、时间范围、是否生成快照及统计对象，再查交易细节。

### 13.05 导出 BIR Excel 报告

**入口：**主菜单 → 日终报告 → BIR 报告。

**前提：**本地有可用且审核通过的 BIR 配置，以及选定期间所需已生成的日报和业务数据。登录不要求 BIR，不代表 BIR 导出不再需要这些资料。

1. 选择开始、结束日期，包含首尾最多 31 个日期。
2. 点击“下载”。
3. 系统生成工作簿后弹出保存框，选择文件夹和名称，保存 `.xlsx`。
4. 等待 `Downloaded: ...` 提示，再在目标文件夹核对文件。

工作簿包含 E-1 至 E-5 等工作表；当前实现中 E-1 为销售汇总，E-2/E-3 为 SC/PWD 明细，E-4/E-5 主要为表头。表格按模板生成且设有保护，应保留原件用于核对，不要手工修改数字后当系统原始输出。

开始日期早于 BIR 审核时间时可能被自动截断；结束时间早于审核时间会拒绝查询。缺少日报、审核资料或模板时无法靠重复点击解决，按 16.12 处理。这里描述的是本系统文件生成规则，不是对报送合规性的认证。

### 13.06 导出 E-Journal 电子流水

**入口：**主菜单 → 日终报告 → E-Journal。

1. 选择起止日期，包含首尾最多 31 个日期。
2. 点击“下载”。
3. 有可导出数据时弹出系统保存框，选择文件名和目录，保存 `.txt`。
4. 等待下载成功提示，检查文本文件日期和相关订单内容。

E-Journal 是本地电子流水，来源于保留的订单/付款/退款与报告票据信息，不是数据库完整备份，也不会发送服务器。没有可导出内容时提示没有报告；取消保存框不会产生成功文件，也不属于收银失败。

### 13.07 导出日期太长或文件找不到

BIR/E-Journal 单次最多包含首尾 31 个日期。导出更长历史时拆成多段，例如 1—31 日、下一月对应区间，并在文件名中标明范围。

下载成功以保存框选定的最终路径为准，不一定在桌面；可从成功提示记录路径。写入失败时换成有权限的本地目录，检查磁盘空间与同名文件是否被占用，再重试导出。导出重试不需要重新收款或重新生成原交易。

## 14 交接班、退出登录与退出应用

### 14.01 正确结束自己的班次

**入口：**主菜单底部“交接班/End Your Shift”；或员工页当前登录人的 OUT。侧栏交接班入口受当前账号考勤开关影响。

1. 先处理未完成订单。系统检查当前本地范围的未完成数量，不应理解成只查本人刚收的单。
2. 若提示仍有未完成订单，点击提示进入线下订单，逐一结账、完成、清台、取消或按授权退款。
3. 再点击交接班。门店要求签退照片时先拍照确认。
4. 在“手头现金”输入清点的实际金额并确认，或按门店制度选择自动计算。
5. 系统完成下班记录和班次报告快照，显示本班次报告。
6. 核对报告，点击“关闭”，系统退出登录。

**注意：**自动计算不等于清点实体现金。手头现金弹窗取消会中止当前交接流程；但如果已成功签退并显示报告，关闭报告是退出登录，不是撤销签退。

### 14.02 仅退出登录会不会签退

**入口：**主菜单底部“退出登录/Logout”。

系统先检查当前用户是否仍有本地活动班次。有班次时提示选择继续交接班，或按提示仅退出登录。仅退出不会自动结束班次，后续登录可能继续使用这个尚未结束的班次。

如果只是换人临时登录，应先与店长确认是否需要完成现金交接。不要把“我已经退出账号”当作“我的班次已结束”的证明；可在员工页或班次报告核对签退时间。

### 14.03 关闭应用前做什么

保存当前操作、确认收款/退款结果，按门店制度完成班次和日报后，再正常关闭 Windows 应用窗口。正常退出不会删除已提交订单；临时选菜、尚未提交的录单表单等页面草稿没有持久保存承诺。

程序关闭期间不能执行自动出餐等定时操作。应用重开后可恢复检查，但不能保证关机时顾客现场交餐行为被记录。不要直接断电或在收款确认中结束进程。

## 15 功能七：设置与商场认证

### 15.01 系统设置能改什么、能看什么

**入口：**主菜单 → 设置 → 系统设置。

可切换语言，查看当前版本、餐厅名称、POS 终端号和序列号。当前语言选择虽然沿用了部分旧翻译键，实际控制应用界面语言，不代表配置打印机。

POS 号和序列号属于显示信息，不是在线绑定入口。序列号为 `-` 时可能缺少相关本地税务资料；普通登录和现金流程不一定因此不可用，但税务导出可能受限。修改餐厅名称、POS 或 BIR 资料应由维护人员处理。

### 15.02 商场认证支持哪几类

**入口：**设置 → 商场认证。

| 商场 | 默认文件目录 | 设置字段 | 主要输出 |
| --- | --- | --- | --- |
| SM Mall | `C:\SIA`（Windows 固定目录） | 无需页面中的租户/终端字段 | 月份命名的 transactions 与 transactiondetails CSV |
| Parqal | 用户选择文件夹 | Tenant ID、Tenant Key、Terminal No | `sales_...xml` 日终销售文件 |
| Megaworld | `D:\Megaworld`，也可另选 | Mall Partner Code ID、POS Terminal ID | S/H/D 文本数据文件及 Z 前缀 PNG 日终图片 |

这些是本地文件生成，不是联网报送或商场自动验收。文件生成成功后仍需按商场实际交付制度处理；本次没有核验商场接收系统。

### 15.03 保存商场设置

1. 选择正确商场。**切换商场会重置认证字段**，先记录原配置。
2. Parqal/Megaworld 点击“选择文件夹”，选择可写目录。SM 使用固定目录。
3. 按商场提供的实际资料填写对应字段，不能首尾带空格。
4. Parqal：Tenant ID、Tenant Key、Terminal No 均最多 25 字符。
5. Megaworld：合作代码最多 8 字符，POS Terminal ID 最多 4 字符。
6. 点击“提交”，等待成功，再确认目录和字段。

Parqal 保存会检查本地已审核 BIR 资料；错误提示可能沿用旧版 Merchant Dashboard 指引，但本纯离线客户端没有该后台入口。应由维护人员准备相应本地配置，不要照旧提示寻找联网设置。

商场 POS Terminal ID 是该文件协议的字段，和系统当前恢复的真实 POS 终端号用途不同；填写它不会改变应用登录的终端身份。

### 15.04 补充生成商场文件

**入口：**设置 → 商场认证 → 补充生成认证文件。

1. 先提交并保存正确商场设置。补生成使用已保存设置，不要只改表单但忘记提交。
2. 确认页面显示的文件目录存在或可创建且当前 Windows 用户有写权限。
3. 选择日期范围，结束不能晚于今天；包含首尾最多 7 个日期。
4. 点击“确认”，等待完成或警告。
5. 到指定目录检查文件名称、修改时间和日期范围。

Parqal 和 Megaworld 生成依赖相应 BIR 与已生成的本 POS 日报；缺资料时可能返回缺失表名或警告，不能把“请求结束”当作文件完整。SM 没有交易时可能生成空数据表头文件并提示无交易/明细。

重新补生成会写入同名输出，SM 的同月文件可能被重写为选定范围的内容。若需要保留此前交付的更宽范围文件，应先复制归档，再补生成。没有撤销文件覆盖的应用按钮。

### 15.05 商场文件与交易成功是什么关系

SM 配置下，登录/恢复会话后会尝试初始化或增量维护最近约 30 天 CSV；普通现金收款、手工录单和退款成功后还会尝试追加单笔记录。文件操作失败只记日志，不应把已经成功的收款/录单/退款再次做一遍。历史数据或缺失文件可使用补生成核对。

Parqal/Megaworld 在日终快照保存后尝试自动生成对应文件，也可通过补生成入口按日期重新生成；普通单笔收款不会自动完成全部日终文件。缺日报时先检查日报；目录无权限时先修复目录。需要帮助时保留商场类型、日期、目标路径、警告文字和对应 POS。

## 16 常见问题与故障处理

### 16.01 登录提示 Account is not found

**症状/关键词：**账号不存在、账号找不到、登录失败、Account is not found。

**可能原因：**账号拼写不同、本地数据库没有该账号，或账号在本地被停用。线上可用不代表本机已有可用账号。

**处理步骤：**检查账号大小写/空格和录入方式 → 确认使用正确门店安装环境 → 请维护人员核对本地账号是否存在且启用。不要创建假账号、尝试默认管理员密码或删除数据库。仍不能登录时提供账号名称、餐厅、报错时间和错误原文，勿提交密码。

### 16.02 登录提示 Password is incorrect

**症状：**密码错误、Password is incorrect。

检查输入法、Caps Lock、数字键盘和是否回填旧密码；重新输入已确认的本地密码。当前客户端没有忘记密码/在线重置功能，需要维护人员按授权方案处理本地账号。不要把明文密码贴入日志、截图或知识库。

### 16.03 提示缺少本地餐厅或 POS 数据

**症状：**`Local restaurant configuration is missing`、`未找到 ... 对应的餐厅设置`、`Local POS data is missing. Please prepare the local database.`。

**原因：**本机缺少门店收银配置或可用真实 POS 数据。`POS01` 被当前离线登录明确排除，它是旧在线虚拟终端标记，不能当默认终端补用。

**处理：**停止营业录单并联系维护人员；确认数据文件位置是否正确、迁移是否完整、账号所属门店是否正确及历史终端资料是否存在。本版没有登录绑定弹窗或服务器同步兜底，不能用“联网再试”“强制绑定 POS01”解决。

### 16.04 桌台管理或排队点餐菜单不见了

主菜单最多 7 项，两个点餐入口受本地门店开关控制。先确认另外 5 项是否正常，并向店长核对该门店是否应支持此模式。若配置本来就关闭，入口隐藏是正常行为；两种都关时默认显示线下订单。配置需要调整时由维护人员处理，当前设置页没有点餐开关。

### 16.05 菜单空白、商品缺少或没有桌台

先确认选择了正确门店/区域、相关点餐功能已开启，并滚动对应列表查看。空分类会隐藏；本地没有产品、有效规格或桌台资料时界面无法凭空生成。请维护人员核对本地菜单、有效状态、规格/选项、区域桌台及迁移情况。

“找不到未完成单”还需检查桌台订单列表的默认日期范围；历史单改用线下订单查询。不要通过新增重复订单尝试“刷新出来”。

### 16.06 点击收款后不确定是否已经成功

**适用：**卡顿、闪退、确认框关闭、提示不明、担心重复收费。

先保留实际收现金情况，再在线下订单按时间/桌台找到原单。核对支付成功状态、SI、支付时间、订单追踪；必要时查看电子版。已付就不要重收；原单未付且仍可结账则继续原单。无法确认时记录原单编号、POS、实收、找零和错误交维护人员。

不要因为没有打印小票、没有开钱箱、没有商场文件或列表暂未刷新，就判定支付失败并重录。

### 16.07 收款按钮灰色或 Enter 没反应

普通 CASH 收款要求实收不少于应收；还在创建支付记录时也会禁用。先核对实收、找零、渠道和页面是否仍加载。键盘焦点在表单字段内或已有弹窗时，Enter 不会作为普通收款快捷键。

手工录单状态中现金键盘禁用是正常行为，应核对手工信息后点击收款。若仍无法操作，记录当前金额和模式，不要反复快速点按钮。

### 16.08 不能输入 0.50 等不足 1 元的现金

**已核实的当前限制：**现金键盘禁止空输入以 `0` 或 `.` 开头，因此这类金额无法正常直接输入。不要按 `50` 代替，也不要虚构实收现金以使按钮可用。请店长/维护人员安排处理；该限制不是网络或键盘设备故障。参见 07.03。

### 16.09 想取消却只能退款，或找不到退款按钮

未付订单按允许状态取消；已经付款要退款。线下订单详情的退款按钮需要退款权限，且支付状态应允许退款。已退款、退款中或不符合条件时按钮会隐藏或操作被拒绝。

先检查付款状态和账号角色，由有授权的人员处理。当前界面不支持任意部分退款金额，也不要借用其他账号密码或从隐藏入口绕过门店审批。

### 16.10 接单、出餐或完成操作报状态错误

常见文字包括 `Only pending orders can be taken.`、`Only queue orders can be served.`、`Only taken orders can be served.`、`[AWAITING_PICKUP] ... [COMPLETE]`、`payment is not available before payment!`。

刷新原单，看是否已被其他操作或定时任务改变。接单要求待处理；出餐要求排队且已接单；排队完成要求待取餐；桌台完成要求已接单并已付。先完成前置步骤，再操作。退款中先处理退款状态，不直接改表里的状态值。

### 16.11 电子副本看不到或生成失败

先确认选中了正确订单及符合预览条件的状态。普通进行中未付单可能没有支付凭证；历史迁移单可能缺付款记录或票据快照。报表副本还需要选好班次/实时范围，历史日终副本按钮并非在所有日期选项下提供。

刷新原单/重选报告后再试。若支付状态已成功，不要为生成副本再次收款。记录订单号、预览类型（支付/退款/报告）和错误文字交维护人员。

### 16.12 BIR 无法下载或提示没有报告

**检查顺序：**日期不超过包含首尾 31 天 → 对应期间日报已生成 → 本地 BIR 已审核且资料可用 → 时间不早于审核范围 → 报告模板存在 → 文件目录可写。

`bir files cannot be downloaded if they are not opened!` 通常表示缺少可用 BIR 资料；`End of day report not generate.`、`No Z-Reading/End of Day Report was generated in this period.` 或“没有报告”可能与日报快照缺失有关。提示 `BIR report template not found` 应检查安装资源。

保存框取消只代表没有保存，不能当作文件已下载。当前纯离线客户端不提供 BIR 在线申请入口，交由维护人员处理本地资料；不要随意改审核时间。

### 16.13 日终生成按钮灰色、找不到按钮或数据不更新

“生成报告”只在日终 → 实时报告下出现；当天已经生成则禁用。先确认选项和本 POS 日报状态。历史补生成不再弹窗，不应把“没有日报提示”当失败。

若今天生成后还有交易，已有快照不保证自动变成最新数据。记录生成时间、后续交易和实际报告周期，交维护人员核对。不要删除日报记录或重复修改机器日期强制生成。

### 16.14 交接班一直提示有未完成订单

打开待处理订单或线下订单，查待处理、已接单、待取餐状态。可能是已经收钱但还没出餐/完成、已付桌台没清台、未付单未取消，或范围内其他员工的订单。

核实现场业务后按规则结账、出餐、完成、取消、退款或清台，再发起交接班。不要为了签退盲目把未交付订单标完成；无法判断归属时由店长安排。退出登录也不等于签退完成。

### 16.15 拍照黑屏或 Unable to open camera

先确认摄像头连接正常，未被其他软件独占；检查 Windows 相机隐私设置是否允许桌面应用访问，关闭占用后重新打开拍照窗口或应用。核对预览是否出现，再拍照确认。

登录拍照若被本地配置要求，无法靠普通取消跳过。普通打卡/签退拍照取消会中止相应操作，未成功前不要记作打卡完成。仍失败时提供摄像头型号、错误原文及发生在登录/上班/下班哪个阶段；如配置需要改变交维护人员处理。

### 16.16 提示先签到、已经签到或没有活动班次

“请签到”可能是未上班或仍在休息；先在员工页检查员工和时间，休息中先恢复工作。“你已签到”表示已有工作记录，不要重复创建班次。

`No active clock record found.`、`Already clocked in somewhere else`、`Already clocked out somewhere else` 属于本地考勤状态提示，不要据此断言另一台机器在线占用。纯离线版不能获取其他机器实时状态，维护人员应核对迁移/本地打卡记录。

如果签退后生成班次报告报错，签退记录可能已经保存；先核对实际下班时间，再处理报表，不要直接重复签退或重新建班次。

### 16.17 PWD/SC 不显示或证件号被占用

入口不显示时检查本地门店优惠开关；手工录单还受国家设置影响。提交失败时先补齐姓名、证件号、PWD 有效日期和优惠人数。

提示同日证件已用时，检查当前 POS、当天同类优惠记录、号码是否大小写/空格差异以及退款历史。当前校验含部分退款相关状态，退款后不保证释放。不要改写证件号、换类别或重建单来绕过校验；由店长核实资格和记录。

### 16.18 手工录单提示 SI/OR 重复或格式不对

格式仅允许 1—20 个英文字母、数字或短横线，不接受空格/中文，也不接受刚好 20 位纯数字。重复提示可能指本机同国家门店已有该凭证。

先检查纸票原号、是否已录过、当前是否在重做同一交易。已录成功时停止重复提交；真正输入错误才按凭证更正。修改纸票号码制造“唯一号”不能解决重复入账问题。

### 16.19 手工录单表单确认了，为什么订单还没入账

手工表单“确认”只校验并保存页面草稿。返回结账页后，还要核对并点击“收银/Charge”，等支付成功。若期间已经关闭页面，草稿可能丢失。

重录之前先查线下订单，确认原单未成功入账，避免把“没看到成功弹窗”误当完全没有记录。

### 16.20 清台或换桌失败

清台提示 `You have orders that have not been completed...` 时，先检查未付款、待处理和退款中等阻塞单；目标桌换桌提示未处理订单时，先完成/取消目标桌对应业务。

缺 `table_uuid`、`Table info does not exist`、订单已完成或目标桌不存在时，核对是否从正确桌台入口进入，以及本地桌台迁移是否完整。不要清除数据库里的订单来释放桌台；历史三天外遗留记录应由维护人员单独核对。

### 16.21 找不到刚才的订单或订单突然消失

先取消状态限制并刷新，清空桌名，扩大创建日期范围，滚动列表加载更多；完成、取消或退款后订单可能不再属于当前筛选。菜单临时草稿未正式提交时本来就不在订单列表。

仍找不到时，核对是否换了 Windows 用户、安装包或数据目录，是否登录其他餐厅，以及是否恢复过旧库。不要立即重收款，先用现金事实和订单追踪核对。

### 16.22 班次、产品和日终报告金额不一致

先统一：当前门店与 POS、报告起止时间、员工/全部范围、当前/历史班次、商品分类、是否使用保存快照、完成与支付时间，以及退款是否跨周期。

商品金额、实付、含税销售、服务费、折扣、净额各自口径不同；周/月也不是固定自然周/月。核对少量代表订单和最终付款明细，再比较汇总。盈亏 0 不能单独证明现金无差额。仍有差异时保留报告范围和样本订单给维护人员复核。

### 16.23 提现提交后取消了手头现金弹窗，要不要重提一次

不应直接重提。提现第一步成功后已保存，后续弹窗取消不撤销提现。先重选当前班次检查提取金额和资金变化；确认记录确实未写入才按真实业务继续。重复提现记录由店长和维护人员核对，页面没有直接撤销/删除入口。

### 16.24 商场认证文件没生成或提示缺少本地表

先核对已提交保存的商场类型、字段和目录；日期首尾最多 7 天且不含未来。Parqal/Megaworld 需 BIR 资料与对应日期、本 POS 已生成日报；`restaurant_operation_config`、`restaurant_report_print` 等缺失提示应交维护人员核对。

SM 无交易或缺商品快照会有警告；不能只检查文件存在，还应检查范围和明细。收款成功后文件追加失败不影响已提交收款，不得再次收款补文件。修复数据或目录后使用补生成，并先归档已有同名文件。

### 16.25 导出提示无权限、目录不存在、文件占用或空间不足

检查保存路径、磁盘剩余空间、目录访问权限及同名 Excel/文本是否正在打开。BIR/E-Journal 可在保存框改选有权限的本地目录；商场文件应先修复或重新保存其配置目录。Megaworld 的默认 D 盘在部分机器不存在，应选择实际目录。

导出重试只重做文件操作；不要重建业务订单。系统没有自动把导出文件上传服务器的补救流程。

### 16.26 没有打印机设置、扫码支付或同步按钮

这是当前纯离线精简版的正常范围。这些功能已移除，联网、安装驱动或重新登录都不会恢复。可使用现金、本地手工录单、电子副本和已有文件导出。若门店确实需要这些能力，应提出产品变更，不能照旧在线版操作指南执行。

### 16.27 商品图片或员工照片不显示

本机展示依赖相应本地文件和数据库资源关联。若迁移时只复制 `database.db` 而没有配套 `local-assets/`，图片可能丢失；远程图片地址也不会因联网自动加载。

先确认业务文字/金额是否正常，再由维护人员检查本地文件是否存在、路径和关联是否匹配、是否恢复到错误目录。不要随意删除素材索引。缺图不应被直接判断为订单丢失。

### 16.28 应用闪退、白屏或重启后仍异常

先记下发生时间、操作阶段、错误提示和是否涉及现金已交付；正常重开后优先核实最后一笔交易状态。可从登录页连续点击版本文字 8 次进入日志，见 18。

收集日志后由维护人员检查数据库、安装资源和权限。不要删除 `database.db`、用户数据目录或重装覆盖数据作为第一步；日志也不要先清空。打不开日志时保存系统可见错误，维护人员在关闭应用后备份数据再检查。

### 16.29 订单没有按时间自动出餐或完成

检查订单是否正式创建、已付款并处于正确前置状态；确认应用主进程仍运行、电脑未关机/休眠，门店自动化配置已开启且时间值有效。自动任务不依赖停留订单页，但关机时不能执行。

重新启动和恢复会话后仍不符合预期时，记录创建、支付、接单、待取餐时间及日志；按实际业务可先由店长人工处理。不要不断改系统时间或重复点出餐来“修定时器”。

### 16.30 没有密码、数据损坏或需要换电脑，能否自行重装

重装软件不等于恢复本地账号和历史数据。先停止写入并由维护人员备份现有数据库、资源和配置，再制定恢复/迁移方案。客户端没有自助重置密码、云端找回、数据库合并或一键恢复入口。具体数据恢复流程见 17。

## 17 数据保存、备份和恢复

### 17.01 数据实际保存在哪里

安装包运行时，数据库位于 Electron 当前用户数据目录 `userData` 下的 `database.db`；本地照片和图片通常在同目录 `local-assets/`。Windows 中该用户数据目录通常处于当前用户应用数据区域，**确切子目录须由维护人员按实际安装环境确认**，不要仅凭应用显示名称拼出路径。

开发环境使用项目 `resources/database.db`，它不一定是 Windows 生产收银正在用的那份库。BIR/E-Journal 在用户保存框所选目录；商场文件在商场设置目录。导出文件目录与业务数据库目录不是一回事。

### 17.02 建议的备份操作

**性质：**维护建议；当前应用没有“一键备份”按钮。

1. 确认最后一笔收款/退款状态，按门店流程结束当前业务。
2. 正常退出应用，确认后台进程已退出。
3. 确认实际 `userData` 路径和当前 Windows 用户。
4. 复制整个应用用户数据目录到标明日期、门店和 POS 的独立备份位置，至少包含数据库及 `local-assets/`，保留目录结构。若仍存在 SQLite 辅助文件，先确认程序已完全关闭再由维护人员处理，不要自行删除。
5. 另行归档 BIR、E-Journal 和商场输出文件。
6. 记录应用安装包版本、门店、POS、备份时间与是否已交班，并由维护人员在隔离环境验证备份可读。

仅保存 Excel、CSV 或 E-Journal 不能替代数据库备份；仅复制数据库也不保证图片和凭据等配置完整。备份频率与保留周期由门店制度决定。

### 17.03 恢复和迁移到新电脑

**前提：**由授权维护人员执行，目标应用已关闭，现有目标数据也先备份。

使用匹配版本应用和完整备份，确认数据库、资源和用户目录关系后恢复。新电脑的机器身份和本地终端恢复逻辑可能影响 POS 选择，应先在隔离环境验证门店、菜单、登录、POS、订单与报表，再允许营业。

恢复旧备份会丢失备份之后的本地交易；不同电脑离线生成的数据库没有客户端一键合并功能。不要把多台机器复制成同一 POS 后同时营业，也不要为了登录随意新增 `POS01`。多个备份之间如何合并/补录必须先核对真实现金与订单。

### 17.04 数据安全和日常维护建议

纯离线代表业务不会自动上传，不代表会自动备份。磁盘损坏、误删或错误覆盖仍可能导致数据丢失。定期检查空间和备份，限制普通员工直接访问数据文件。

员工照片、姓名、证件号、凭据及商场 Tenant Key 应按门店数据管理要求保存。后续 RAG 只导入操作文档和脱敏问题样本，不应把生产数据库、密码、照片或证件号作为常规知识材料。

## 18 现场日志与报修

### 18.01 如何进入隐藏日志页面

**入口一：**登录页底部版本文字，快速连续点击 8 次。  
**入口二：**登录后打开左侧主菜单，连续点击餐厅名下方版本文字 8 次。

相邻点击间隔应保持较短，超过约 1.5 秒会重置计数。当前文字通常含 `1.0.4`，日志入口并不取决于包版本是否为这个数字。

成功后进入开发者日志页，无需 F12 或 DevTools。生产包不一定允许打开调试控制台，因此日志页是现场排查入口。登录页可进入不代表其中日志可以随意公开。

### 18.02 查找和复制故障日志

1. 选择故障前后时间；可选最近一小时、今天、最近七天。
2. 先选 error 或 warn，再根据需要放宽为全部。
3. 选择来源 main、renderer、process 或 ipc；不确定先选全部。
4. 用 tag 关键词过滤，可选模糊或精确匹配。
5. 按最新/最旧排序，点击查询或刷新。
6. 点击 message 查看完整消息、stack 和 context。
7. 复制单条详情或当前页日志，保留到报修资料中；长列表复制当前页不代表复制了全部历史日志。

系统自动收集部分主进程和全局错误，但不是每条渲染层普通输出都会持久保存，所以“没日志”不能直接证明操作没有发生。

### 18.03 什么时候清空日志

日志页提供“清空”并有确认；执行会删除本地日志表记录。普通订单不因此被取消，但故障证据会丢失。只在已经保存必要日志且确有维护需要时使用，不要把它当作解决收款、数据缺失或打印问题的常规按钮。

### 18.04 提交一份可处理的报修记录

建议复制以下模板填写，敏感数据脱敏：

```text
发生时间：YYYY-MM-DD HH:mm（门店本机时间）
门店名称 / POS 终端号：
应用来源/安装包版本；界面显示版本：
所在页面与操作入口：
订单号 / SI / 取餐号（如涉及）：
操作前的订单状态和付款状态：
具体做了哪几步：
预期结果 / 实际结果：
错误文字与相关日志：
真实现金是否已收到或已退回、金额与找零：
是否重启、换用户、恢复过数据或重复点击：
导出类型、日期范围和目标目录（如涉及）：
是否已做备份；最近可用备份时间：
```

不提供账号密码、完整证件号、Tenant Key 或不必要的员工照片。业务状态不明时先冻结重复操作并核对，不用报修过程再造一笔收款来复现。

## 19 常用问答速查

### 19.01 这个系统主菜单到底有多少项

最多 7 项：桌台管理、排队点餐、线下订单、收银员报告、日终报告、员工管理、设置。前两项受门店开关控制，实际显示 5—7 项。交接班、退出登录和隐藏日志不计入。详见 03.01。

### 19.02 没有网络还能营业吗

可以，这是纯离线版的正常使用方式，前提是本地账号、菜单、餐厅和 POS 已准备。它不会在联网后自动同步交易。详见 01.01、02.01。

### 19.03 能扫码支付、核销优惠券或连接第三方外卖平台吗

当前版不支持。手工录单中的平台名称只是订单分类，不会发起付款、核销或拉单。详见 01.02、08.01。

### 19.04 为什么登录没有让我绑定 POS 或 BIR

该登录绑定流程已经移除，系统恢复已有本地终端；BIR 资料在需要税务/报表功能时另有前提。缺 POS 数据联系维护人员，不能用 POS01 代替。详见 02.03、16.03。

### 19.05 开班资金自动计算会带出上一班余额吗

不会。当前登录流程的自动计算按 0 提交；真实备用现金应手工输入。详见 02.04。

### 19.06 下单和结账有什么区别

餐后“下单”先保存菜品，之后可加单再结账；“结账”进入核对金额和收款流程。餐前/排队初次进入结账是临时草稿，支付流程才创建正式单。详见 05.04—05.05、06.01。

### 19.07 顾客加菜要新开一单吗

餐后桌台顾客继续在同一桌台选菜并下单，系统形成同组加单，最终整组结账。先核对原单未结束，勿误选另一桌。详见 05.04。

### 19.08 已下单的菜能删掉吗

未付且符合状态的桌台订单可在结账页减菜；填的是剩余数量。已付款不能靠减菜撤销，应按退款/纠错流程处理。详见 07.07。

### 19.09 减免 20% 是二折吗

不是。减免 20% 表示扣除商品基数的 20%，相当于该基数支付 80%；最终总额还可能含服务费等。详见 07.04。

### 19.10 可以同时用普通折扣、PWD 和 SC 吗

当前结账选择以一种优惠计算为主，切换会替换/清空旧选择，不能当作可叠加多个优惠。优惠人数变化还需重算 PWD/SC。详见 07.04—07.05。

### 19.11 手工录单确认后现金键盘灰色是不是故障

不是。手工模式使用独立金额，普通现金输入禁用；核对手工内容后仍需点击收款完成入账。详见 08.02。

### 19.12 支付成功弹窗的完成会把排队订单也全部完成吗

不能这样理解。它主要结束收款页面流程；排队订单还需要按状态出餐和取餐完成，或由已配置的自动任务推进。详见 06.02、07.02。

### 19.13 收到钱后没有纸票怎么办

本版没有打印功能。先检查付款状态，按需查看电子版或导出 E-Journal；不要因没有纸票再次收款。详见 09.09、13.06。

### 19.14 已接单是不是表示已经收钱

不是，履约与支付分开。餐后桌台已接单仍可能未付款，必须核对付款状态。详见 09.03。

### 19.15 订单处理完后列表不见了，是被删除了吗

可能只是当前状态筛选不再匹配。改“全部”并点刷新，再按日期/桌台查找。取消和退款也会保留历史。详见 09.01、16.21。

### 19.16 已支付订单想退一部分钱可以直接输入金额吗

当前普通退款弹窗没有部分金额字段，按整单退款处理；不能承诺支持部分退款或自动原路退回。详见 09.07。

### 19.17 退款成功后同一 PWD 证件能立即再用吗

不能保证。当前本 POS 同日同类优惠校验包含退款等相关交易状态，应先核实原记录。详见 07.05、16.17。

### 19.18 退出登录是不是结束班次

不是。选择仅退出会保留活动班次；完整交接班需要检查订单、处理现金、签退和班次报告。详见 14.01—14.02。

### 19.19 日终报告和班次报告有什么区别

班次报告按收银员及打卡班次看资金和交易；日终报告按门店/POS 报告周期形成销售税务快照。二者不会自动替代签退或对方报告。详见 12.01、13.01—13.03。

### 19.20 周报告就是本周一至周日吗

不是，预设从今天往前 7 天至今天，含首尾可能有 8 个日期；需要自然周用自定义。月预设也是滚动日期。详见 12.05。

### 19.21 日终已经生成但又来一笔订单怎么办

先保留订单和时间，核对已生成报告周期并联系维护人员。已有快照不保证自动回写，不能直接删日报重做。详见 13.02、16.13。

### 19.22 BIR 和 E-Journal 最多导出多久

每次包含起止日期最多 31 个日期；更长分段导出。商场文件补生成不同，每次最多 7 个日期。详见 13.05—13.07、15.04。

### 19.23 下载完的文件在哪里

BIR/E-Journal 在保存框选择的最终目录；商场文件在已保存的商场配置目录，不保证是桌面。成功提示可用来核对实际路径。详见 13.07、15.02。

### 19.24 要改菜价、新增员工或重置密码去哪里

当前客户端没有这些完整基础资料编辑入口。由维护人员按本地部署方案处理；员工管理是考勤、菜单页是点餐。详见 03.03。

### 19.25 只保留 E-Journal 能恢复全部订单吗

不能。流水导出不是完整数据库备份，需要备份实际用户数据目录及本地资源。详见 17.01—17.03。

### 19.26 出问题可以先删除数据库让程序重建吗

不可以作为常规排障。空库缺门店账号和菜单，也会丢失历史交易。先保存错误和日志，关闭后备份，由维护人员检查。详见 16.28、17、18。

### 20.02 供后续 RAG 建库的文件和字段

本手册同时交付 Markdown 和 HTML，正文一致；Markdown 适合入库，HTML 适合员工阅读。另提供按章节生成的 JSONL 知识片段与来源清单，作为后续开发的可选起点，未创建实际向量库、检索服务或问答 Agent。

建议导入 Markdown 或 JSONL 二选一，避免重复入库。每条知识保留文档编号、文档版本、编写日期、项目版本、章节编号、标题路径、适用范围、验证方式和源码来源。JSONL 中的来源标记可查“来源清单.json”；片段是操作知识，不是实时业务数据。

中文检索应同时覆盖中英文术语、错误原文和通俗问法，例如“签退不了”“日结按钮灰色”“没有小票”“SI 重复”“只点确认为什么没录进去”。不要只切按固定字符截断的无标题文本，尽量保留步骤、前提和结果在同一知识块内。

### 20.03 建议问答 Agent 的回答方式

回答操作问题时先说明适用页面/模式和前提，再给步骤、成功标志及失败处理，并引用章节编号。询问状态/金额异常时先区分“临时草稿、正式订单、付款状态、履约状态、报告快照”。

对版本明确删除的在线支付、同步和打印功能，应直说当前纯离线版不支持；对账号配置、数据库修复、BIR 资料和恢复历史，转交授权维护人员，不编造后台入口或 SQL 修复步骤。没有订单/日志实时工具时，不要说“我已查到你这笔订单”“已经退款”或“已经备份”。

对状态不明的收退款，首先建议查询原单和核对现金，避免重复操作。只有用户授权且未来集成了对应可靠业务工具时，Agent 才能按单独的执行规则办理，不把这份只读使用指南当自动退款授权。

### 20.04 如何保持知识不过期

界面文案、菜单数量、支付方式、POS 恢复、优惠校验、订单自动流转、日报周期或文件协议改变时应更新相关章节和问答。以当前离线源码为事实依据；历史在线前端/后端只是比较参考，不能覆盖本版已经删除的行为。

本次没有可引用的 Git 提交号，因为当前目录已移除 Git 元数据；来源清单使用读取到的源文件路径和 SHA-256 指纹记录基线。指纹只说明内容版本，不表示完成了 Windows 实机验证。
